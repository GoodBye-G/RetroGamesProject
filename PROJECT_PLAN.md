# 🕹️ Проект: Ретро-аркада в Telegram Mini App (C++ Бот + Web)

Документ описывает архитектуру проекта, структуру папок для командной работы, распределение ролей и этапы сборки единого приложения.

---

## 1. Архитектура и структура папок

Проект разделен на серверную часть (Telegram-бот на C++) и клиентскую веб-часть (HTML5/CSS/JS), которая открывается внутри Telegram через механизм **Web Apps**. Для изоляции работы каждого участника в папке `webapp/games/` выделены отдельные директории.

```text
retro-arcade-bot/
│
├── bot_cpp/                  # Зона ответственности Участника 1 (Бэкенд)
│   ├── CMakeLists.txt        # Файл сборки C++ проекта
│   ├── main.cpp              # Логика бота и кнопка запуска WebApp
│   └── include/              # Заголовочные файлы и библиотеки (tgbot-cpp)
│
├── webapp/                   # Веб-приложение (Фронтенд)
│   ├── index.html            # Главное меню выбора из 6 игр (Участник 1)
│   ├── assets/               # Общие шрифты, иконки, звуки (Участник 3)
│   ├── css/
│   │   └── theme.css         # Единые стили и ретро-палитра (Участник 3)
│   │
│   └── games/                # Изолированные папки разработчиков
│       ├── si/               # 2 игры Участника 1 — СИ (game_1/, game_2/ — переименовать под свои игры)
│       ├── sv/               # 2 игры Участника 2 — СВ (game_1/, game_2/ — переименовать под свои игры)
│       └── sha/              # 2 игры Участника 3 — ША (game_1/, game_2/ — переименовать под свои игры)
│
├── presentation/             # Материалы для защиты проекта (Участник 3)
│   └── presentation.pptx     # Итоговая презентация
│
├── PROJECT_PLAN.md           # Этот файл с планом работы
└── README.md                 # Инструкция по запуску проекта
```

### Принцип взаимодействия компонентов
1. Пользователь отправляет команду `/start` боту, написанному на **C++**.
2. Бот возвращает сообщение с Inline-кнопкой (`WebAppInfo`), ведущей на хостинг с веб-частью (например, **GitHub Pages**).
3. Внутри Telegram открывается главный экран `webapp/index.html` с меню выбора из 6 игр.
4. При выборе игры происходит переход в соответствующую папку разработчика (`games/<инициалы>/...`). В каждой игре присутствует кнопка возврата в главное меню (`../../../index.html`).

## 2. Распределение ролей и задач

### 👤 Участник 1 — Архитектор / Тимлид / Разработчик (2 игры + Бот)
* **Архитектура:** Создание репозитория, настройка структуры папок и базового шаблона `index.html`.
* **Бэкенд (C++):** Написание Telegram-бота (с использованием библиотеки `tgbot-cpp` или аналогов), настройка кнопки вызова Web App.
* **Разработка игр:** Создание **2 ретро-игр** в папке `webapp/games/si/`.
* **Интеграция:** Сборка кода от всех участников в единый проект, настройка навигации в `index.html` и публикация веб-части на хостинге (GitHub Pages).

### 👤 Участник 2 — Разработчик игр (2 игры)
* **Разработка игр:** Создание **2 ретро-игр** строго внутри своей папки `webapp/games/sv/`.
* **Адаптация под мобильные устройства:** Реализация экранных кнопок управления (тач-контролов), так как Telegram чаще используется на смартфонах.
* **Навигация:** Добавление в интерфейс каждой игры кнопки «В главное меню» со ссылкой на `../../../index.html`.

### 👤 Участник 3 — Разработчик (2 игры) + Дизайн и Презентация
* **Разработка игры:** Создание **2 ретро-игр** в папке `webapp/games/sha/`.
* **Единый стиль:** Подбор ретро-шрифтов (например, *Press Start 2P*), цветовой палитры и оформление файла `webapp/css/theme.css` для всего проекта.
* **Презентация:** Подготовка слайдов для защиты проекта (идея, стек технологий, схема работы C++ бота и WebApp, демонстрация игр, вклад каждого участника).

## 3. Технические требования для безболезненной склейки

Чтобы при объединении папок проект заработал сразу и без конфликтов, все участники соблюдают следующие правила:

1. **Изоляция файлов:** Каждый работает только в своей директории (`si`, `sv`, `sha`). Изменять чужие папки и главный `index.html` запрещено (главное меню обновляет только Архитектор).
2. **Относительные пути:** Все картинки, звуки и скрипты внутри игры должны подключаться по относительным путям внутри своей папки (например, `./script.js`, `./assets/hit.wav`).
3. **Интеграция с Telegram:** В `<head>` каждой HTML-страницы игры необходимо подключить официальный скрипт Telegram Web App:
   ```html
   <script src="https://telegram.org/js/telegram-web-app.js"></script>
   ```
   И при загрузке страницы вызывать разворачивание на весь экран:
   ```javascript
   window.Telegram.WebApp.expand();
   ```
4. **Единая кнопка выхода:** В каждой игре должна быть кнопка возврата в меню:
   ```html
   <a href="../../../index.html" class="back-btn">← В меню</a>
   ```

## 4. Этапы реализации проекта

### Этап 1. Инициализация и каркас
* Выбор 6 уникальных ретро-игр (чтобы не было дубликатов).
* Создание репозитория и базовой структуры папок.
* Написание минимально рабочего C++ бота, который открывает пустую заготовку `index.html`.
* Утверждение единой цветовой гаммы и шрифтов (`theme.css`).

### Этап 2. Параллельная разработка
* Участник 1 пишет 2 игры в `si/` и дорабатывает логику C++ бота.
* Участник 2 пишет 2 игры в `sv/`.
* Участник 3 пишет 2 игры в `sha/` и параллельно собирает структуру презентации.

### Этап 3. Склейка и тестирование
* Участники 2 и 3 передают свои готовые папки Участнику 1 (через Git Pull Request или архивом).
* Участник 1 помещает папки в `webapp/games/`, прописывает рабочие ссылки в `index.html` и загружает проект на хостинг.
* Командное тестирование: проверка запуска бота, корректности отображения игр на экранах телефонов, работы кнопок управления и возврата в меню.

### Этап 4. Подготовка к защите
* Финализация презентации (добавление скриншотов готовых игр и схемы архитектуры).
* Распределение речи на защите: каждый участник демонстрирует и объясняет свою часть работы (архитектура и бот на C++, механика игр, дизайн и презентация).
